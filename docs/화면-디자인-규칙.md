# 화면 디자인 규칙 — 방향 B (판정 계기판)

> 2026-08-31 확정. 시안 3안 중 **B(판정 계기판)** 채택.
> 근거: 이 화면의 목적은 읽는 것이 아니라 **"이 일을 받을까 말까"를 빨리 정하는 것**이다.
> 사용자가 곧 판단자이고, 심사위원이 보는 첫인상에도 같은 화면이 쓰인다.
>
> 이 문서는 **감으로 고치는 것을 멈추기 위한 기준**이다. 화면을 고칠 때 이 값 밖의 색·크기·간격을 새로 만들지 않는다.
> 새 값이 필요하면 이 문서를 먼저 고치고, 그다음 코드를 고친다.

---

## 0. 전환 비용 (실측)

B는 어두운 화면이고 현재 앱은 밝은 화면 고정이라 전면 교체처럼 보이지만, 실제로는 아래 7곳뿐이다.

- `app/globals.css:5` — `:root { color-scheme: light; }`
- `app/globals.css:15` — `.card` 의 `bg-white`
- `app/globals.css:27` — `.btn-ghost` 의 `bg-white`
- `app/page.tsx:94` — `bg-white`
- `components/RequestForm.tsx:68, 110` — `bg-white` 2곳
- `components/VerdictBanner.tsx:11` — `bg-white`

이 7곳을 토큰으로 바꾸고 `tailwind.config.ts` 색 값을 교체하면 나머지는 따라온다.

## 1. 폰트 — 가장 먼저, 단독 최대 효과

**현재 문제**: `app/layout.tsx` 에 웹폰트 로드가 **없다.** 한글이 보는 사람 컴퓨터의 기본 글꼴(맥 = Apple SD Gothic Neo, 윈도우 = 맑은 고딕)로 그려진다. 기기마다 다르게 보이고, 어느 쪽이든 "디자인하지 않은 문서" 느낌의 원인이다.

**쓸 폰트**

| 역할 | 폰트 | 쓰는 곳 |
|---|---|---|
| 제목·본문 | **Gothic A1** (400 / 500 / 700 / 900) | 화면 전체의 기본 |
| 숫자·라벨 | **IBM Plex Mono** (400 / 500 / 600) | 금액, 공수, 건수, S1~S8 라벨, 뱃지 |

숫자를 모노스페이스로 분리하는 것이 계기판 느낌의 핵심이다. 금액과 시간이 자릿수로 정렬돼 비교가 눈에 들어온다.

**적용** — `app/layout.tsx` 에서 `next/font/google` 을 쓴다.

```tsx
import { Gothic_A1, IBM_Plex_Mono } from "next/font/google";

// next/font 는 Gothic A1 의 'korean' 서브셋 이름을 모른다.
// subsets 를 지정하면 라틴만 받아 한글이 폴백 폰트로 그려지므로,
// preload: false 로 두어 서브셋 제한 없이 전체를 받게 한다.
const gothicA1 = Gothic_A1({
  weight: ["400", "500", "700", "900"],
  variable: "--font-sans",
  display: "swap",
  preload: false,
});

// 숫자·라틴 전용이라 라틴 서브셋으로 충분하다.
const plexMono = IBM_Plex_Mono({
  subsets: ["latin"],
  weight: ["400", "500", "600"],
  variable: "--font-mono",
  display: "swap",
});

// <html> 에 두 변수를 붙인다
<html lang="ko" className={`${gothicA1.variable} ${plexMono.variable}`}>
```

> ⛔ **`<head>` 를 직접 쓰지 말 것.** App Router 의 layout 에 `<head>` 엘리먼트를 렌더하면
> Next 가 자동으로 넣어주던 기본 meta(`charset`, `viewport`)가 **사라진다.**
> viewport meta 가 없으면 모바일이 980px 로 렌더돼 화면 전체가 축소되고,
> 반응형 작업이 통째로 무력화된다. 빌드는 통과하고 데스크톱에서는 멀쩡해 보여서 놓치기 쉽다.
> (2026-08-31 실제로 이 방식으로 넣었다가 발견. 확인법: `curl -s <주소> | grep -c 'name="viewport"'` 가 1이어야 한다)

`tailwind.config.ts` 의 `theme.extend.fontFamily` 에도 등록한다.

```ts
fontFamily: {
  sans: ["var(--font-sans)", '"Apple SD Gothic Neo"', "system-ui", "sans-serif"],
  // Plex Mono 에는 한글 글자가 없다. 한글이 섞이면 var(--font-sans) 로 떨어지게 해
  // 시스템 고정폭 폰트로 튀지 않게 한다.
  mono: ["var(--font-mono)", "var(--font-sans)", "ui-monospace", "Menlo", "monospace"],
},
```

## 2. 색 토큰

**현재 문제**: 색 7개 중 3개(`high`/`mid`/`low`)가 전부 심각도용이다. 즉 화면에 있는 유일한 색이 경고색이라, 결과 화면이 온통 빨갛고 **정작 진짜 심각한 항목이 안 튄다.**

**해법**: 액센트(제품의 색)와 심각도(신호의 색)를 완전히 분리한다.

```ts
// tailwind.config.ts — theme.extend.colors 전체 교체
colors: {
  // 바탕 3단계
  bg:      "#11141C",  // 페이지 바닥
  card:    "#191E2A",  // 카드·입력창 표면
  edge:    "#262D3D",  // 테두리·구분선

  // 글자 3단계
  ink:     "#E9ECF4",  // 제목·본문
  soft:    "#AEB6C9",  // 설명문
  mute:    "#78819A",  // 라벨·보조

  // 액센트 — 제품의 색. 강조하고 싶은 값, 주요 버튼에만
  accent:  "#F2A83E",  // 앰버

  // 심각도 — 신호의 색. 판정에만 쓰고 장식으로 쓰지 않는다
  high:    "#FF6D5C",  // 심각
  midsev:  "#F2A83E",  // 주의 (액센트와 같은 앰버를 공유)
  lowsev:  "#78819A",  // 낮음 (mute와 동일)
  ok:      "#56C7B0",  // 안전·수용 가능
},
```

기존 `sub`, `line`, `mid`, `low` 이름을 쓰는 곳이 있으면 각각 `soft`, `edge`, `midsev`, `lowsev` 로 바꾼다.

`app/globals.css` 첫 줄도 함께 바꾼다.

```css
:root { color-scheme: dark; }
```

## 3. 색 사용 규칙

지키지 않으면 지금과 같은 "전부 빨간 화면"으로 돌아간다.

- **액센트(앰버)는 한 화면에 2~3곳만.** 보정 금액, 주요 버튼, 진행 표시. 그 외에는 쓰지 않는다.
- **심각도 색은 판정에만.** 뱃지, 카드 왼쪽 3px 막대, 심각 건수 숫자. 제목이나 본문을 심각도 색으로 칠하지 않는다.
- **본문은 색을 쓰지 않는다.** `ink` / `soft` / `mute` 세 단계로만 위계를 만든다. 강조가 필요하면 색이 아니라 **굵기(700)**로 한다.
- 카드 배경을 심각도 색의 반투명으로 칠하지 않는다. 왼쪽 막대 하나로 충분하다.

---

## 4. 타입 스케일

이 8개 밖의 크기를 새로 만들지 않는다.

| 이름 | 크기 / 굵기 | 폰트 | 쓰는 곳 |
|---|---|---|---|
| display | 30px / 900 | Gothic A1 | 페이지 제목 (믿을구석) |
| title | 22px / 900 | Gothic A1 | 결과 헤더의 프로젝트명 |
| stat | 28px / 600 | Plex Mono | 계기판 큰 숫자, 보정 금액 |
| section | 16px / 700 | Gothic A1 | 섹션 제목 |
| item | 16px / 700 | Gothic A1 | 숨은 작업 항목명 |
| body | 14px / 400 | Gothic A1 | 설명문 |
| meta | 12px / 500 | Plex Mono | 공수, 계약 상태 |
| label | 11px / 500 | Plex Mono | 뱃지, S1~S8, 대문자 라벨 (letter-spacing 0.1em) |

- 본문 줄간격 1.7, 제목 1.35
- 제목에는 `letter-spacing: -0.02em`, 대문자 라벨에는 `+0.1em`
- 숫자가 세로로 정렬되는 곳(금액·공수·건수)에는 **반드시** `font-variant-numeric: tabular-nums`

---

## 5. 간격 · 모서리 · 테두리

- **간격은 4의 배수만**: 4 / 8 / 12 / 16 / 22 / 32 / 48 / 64px
- 카드 안쪽 여백 16~22px, 카드 사이 8px, 섹션 사이 32px, 큰 덩어리 사이 48px
- **모서리는 3px 하나로 통일.** 지금 `rounded-xl`(12px)이 쓰이는데 계기판에는 너무 둥글다. 날카로울수록 도구답다.
- 테두리는 `1px solid edge` 하나. 심각도 막대만 `border-left: 3px`
- **그림자를 쓰지 않는다.** 어두운 바탕에서는 그림자가 안 보이고 지저분해진다. 깊이는 `bg`와 `card`의 밝기 차이로 만든다.

## 6. 컴포넌트 규칙

`app/globals.css` 의 `@layer components` 를 아래로 교체한다.

```css
@layer components {
  .card {
    @apply rounded-[3px] border border-edge bg-card p-5;
  }
  .card-sev {
    @apply rounded-r-[3px] border border-edge border-l-[3px] bg-card p-4;
  }
  .badge {
    @apply inline-flex items-center rounded-[2px] px-2 py-0.5 font-mono text-[11px]
           font-semibold uppercase tracking-[0.1em];
  }
  .btn {
    @apply inline-flex items-center justify-center rounded-[3px] px-4 py-3
           text-sm font-bold transition;
  }
  .btn-primary {
    @apply btn bg-accent text-bg hover:brightness-110 disabled:opacity-35;
  }
  .btn-ghost {
    @apply btn border border-edge bg-card text-ink hover:border-mute;
  }
  .field {
    @apply w-full rounded-[3px] border border-edge bg-card p-4 text-ink
           outline-none placeholder:text-mute focus:border-accent/60;
  }
  .label {
    @apply mb-2 block font-mono text-[11px] uppercase tracking-[0.1em] text-mute;
  }
  .stat {
    @apply font-mono text-[28px] font-semibold leading-none tabular-nums;
  }
}
```

주요 버튼이 검정 배경에서 **앰버 배경 + 어두운 글자**로 바뀐다. 어두운 화면에서 검정 버튼은 보이지 않는다.

## 7. 결과 화면 구조

계기판은 **위에서 아래로 정보가 넓어지는** 3층 구조다. 지금은 모든 카드가 같은 무게라 스캔이 안 된다.

1. **판정 줄** — 프로젝트명(title) + 판정 칩(위험/조건부/수용). 칩은 배경을 심각도 색으로 채우고 글자를 `bg` 색으로. 한 화면에 이 칩 하나만 채운 색을 쓴다.
2. **금액 대비** — 제시 금액 → 보정 금액. 화살표로 잇고, **보정 금액만 앰버 + stat 크기.** 아래에 추가 공수를 mono 작은 글씨로.
3. **숫자 4칸** — 숨은 작업 / 그중 심각 / 계약 범위 밖 / 시간 환산 불가. 4등분 그리드, 숫자는 stat, 심각 건수만 `high` 색.
4. **항목 목록** — `card-sev`. 왼쪽 3px 막대로 심각도, 첫 줄에 뱃지·S번호·공수(오른쪽 정렬), 그다음 항목명(item), 설명(body). **심각도 순으로 정렬**한다.

## 부록 — 하지 말 것

- 이 문서에 없는 색을 새로 만들지 않는다. 필요하면 문서를 먼저 고친다.
- 그라디언트를 쓰지 않는다. 계기판은 단색이라야 값이 읽힌다.
- 애니메이션은 진행 표시 하나만. 카드 등장 효과를 넣지 않는다.
- 심각도 색을 장식으로 쓰지 않는다. 색이 흔해지면 경고가 경고로 안 읽힌다.
- 카드를 더 둥글게 만들지 않는다. 3px이 이 방향의 정체성이다.
