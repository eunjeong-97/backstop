# 믿을구석(Backstop) — 제출 문서 초안

> 원티드 AI Championship 2026 출품작 · 초안 v1 (2026-09-02)
> ⚠️ 공식 제출 양식 미확인 상태의 범용 구조 초안. 양식이 확인되면 문항에 맞춰 재배치한다.
> 데모: https://backstop-seven.vercel.app · 저장소: https://github.com/eunjeong-97/backstop

---

## 1. 한 줄 소개

외주 요청문을 넣으면 **거기 안 적힌 작업**을 찾아내, 공수와 계약 범위 문구를 만들어주는
프리랜서의 사수(Backstop).

## 2. 문제 정의 — 왜 이걸 만들었나

프리랜서가 외주에서 손해를 보는 원인은 가격을 낮게 불러서가 아니라,
**요청문에 안 적힌 작업을 견적에 못 넣어서**다.

- "회원 데이터 이관" 한 줄 뒤에는 비밀번호 해시 호환 실패 → 전 회원 재로그인 사고가 숨어 있다
- "스토어 등록" 한 줄 뒤에는 Apple UGC 규정 대응(신고·차단·필터링) 수십 시간이 숨어 있다
- 이런 항목은 견적서에서 0시간으로 계산되고, "신규 개발 없음·증액 없음" 계약과 만나면
  전액 무상 노동이 된다

그래서 이 도구는 견적 계산기가 아니라 **누락 탐지기**다.

### 사람이 못 하고 AI가 해야 하는 이유

눈앞의 주장은 누구나 검증할 수 있지만, **안 보이는 누락은 검증할 대상 자체가 없다.**
누락을 찾으려면 수백 건의 사고 패턴(스토어 심사 규정, 법정 요건, 계약 조항 관행)이
머리에 들어 있어야 하고, 그게 없어서 손해가 반복된다. 이 도구는 검증 불가능한 것(누락)을
검증 가능한 것(근거 인용이 붙은 후보 목록)으로 바꾼다. 최종 판단은 사람이 한다 —
도구 이름이 '사수'인 이유다.

## 3. 접근 — 어떻게 찾나

### 2단 파이프라인 (추측과 사실의 분리)

1. **Stage 1**: 요청문에 글자로 적힌 것만 구조화. 추론 금지, 근거 원문 인용 필수
2. **Stage 2**: 안 적힌 것을 추론. 업종별 체크리스트가 아니라 **숨는 위치 8개(S1~S8)**를 순서대로 훑는다

한 번에 시키면 "적힌 것"과 "추측"이 섞여 어느 쪽이 틀렸는지 추적할 수 없어서 나눴다.

### 숨은 작업이 숨는 8개 자리 (S1~S8)

실제 위시켓 공고 5건을 손으로 분석해 보니, **업종이 달라도 누락이 나오는 위치는 같았다.**
한 줄로 적힌 큰 일(S1), "준비 중"(S2), "우리가 직접 하겠다"(S3), "아직 안 정했다"(S4),
범위 밖 인접 시스템(S5), 법적·행정 요건(S6), 기다리는 시간(S7), 못 미루는 날짜(S8).
S7·S8은 예시 대신 판단 질문을 앞세운다 — "이 시간은 일한 시간인가, 묶인 시간인가",
"이 날짜가 밀리면 누가 손해를 보는가". 처음 보는 형태도 질문 하나로 자리에 들어온다.

### 추측을 막는 장치 3개

- 모든 항목에 근거 원문 인용 필수 — 없으면 출력 금지
- 확신 없으면 confidence: low + 확인 질문 동반
- 공수는 범위(min~max)로만, 단일 숫자 금지. **금액은 도구가 만들지 않는다** —
  공수에 사용자가 입력한 단가를 곱할 뿐. "그 금액을 어떻게 믿냐"에 대한 구조적 답

## 4. 반복 개선 — 방향을 튼 기록 (개발일지에서)

1. **업종별 체크리스트 → 구조적 위치 8개**: 정답지를 만들어 보니 업종이 달라도 누락
   위치가 같았다. 도메인 접근 폐기
2. **재현율 100% → 무효 선언**: 정답지 작성자와 실행자가 같아 답을 알고 푼 셈.
   숫자를 버리고 측정 체계를 다시 설계했다(홀드아웃 분리)
3. **예시 나열 → 판단 질문**: S7·S8 누락의 원인이 "자리를 안 봐서"가 아니라 "자리의
   정의가 좁아서"임을 출력 재분석으로 확인. 예시 추가 대신 질문 구조로 전환
4. **오염 규칙을 사람 기억 → 기계 검사로**: "홀드아웃을 프롬프트에 인용하지 않는다"는
   규칙은 문서에만 적으면 반드시 깨진다(실제로 한 번 깨졌다). 절 단위 대조 검사기
   (check_holdout.py)를 만들어 커밋 전 통과를 강제
5. **mock 통과 ≠ 동작**: API 키를 꽂은 첫 실호출에서 출력 상한 잘림 버그로 즉시 502.
   실측(output=8,000=상한)으로 원인 확정 후 수정. "키 꽂고 1건"이 가장 싼 통합 테스트였다

## 5. 결과 검증 — 첫 유효 측정

### 방법

- 정답지가 있는 5건은 두 번 오염되어(작성자=실행자, 문장이 프롬프트에 인용됨) 측정에서 제외
- 오염 없는 **홀드아웃 3건**(비대면 진료 플랫폼 / 여행사 ERP / 카드단말기 관리, 길이·업종·
  규제 강도를 벌려 선정)으로만 측정. 실행 전 오염 검사기 통과 확인

### 숫자 (2026-09-02, 1차 측정)

- **high(심각) 재현율: 11/15 = 73%** — 계약 사고로 직결되는 항목 15개 중 11개 발견
- 전체 재현율: 25/32 = 78% · 수용/위험 판정 일치: 3/3

### 도구가 놓친 7개의 패턴 (다음 개선 방향)

- 법과 사업 모델의 충돌 (예: 의료법 유인·알선 금지 vs 플랫폼 수수료 설계)
- 적힌 흐름의 반대편 (예: 예약 기능 뒤의 취소·환불 로직)
- 숨은 비용 구조 (예: 외부 솔루션의 사용량 과금 전가)

### 한계의 정직한 표기

- 정답지 초안은 채점 대상과 같은 계열의 AI(Claude)가 작성했다. 같은 맹점을 공유할 수
  있어, 법·규제 항목은 외부 근거(보건복지부 공고, 플랫폼 공식 개발자 문서)로 대조 검증했다.
  도메인 전문가 검증은 미완이며, 이 한계는 정답지 파일에 명시돼 있다
- 위 73%를 보고 프롬프트를 고치면 이 시험 문제는 오염된다. 개선은 연습용 5건으로만 하고,
  재측정은 새 홀드아웃으로 한다

## 6. 안전·비용 설계

공개 링크 뒤에 API 키가 있으므로 방어를 4겹으로 쌓았다(전 항목 발동 실측 완료).

- IP당 시간당 5회 (6회째 429 확인) · 하루 총 60회 초과 시 예시 모드 폴백
- 입력 6,000자 · 출력 16,000토큰 상한 · 최종선은 선불 크레딧(자동충전 OFF)
- 키가 없거나 장애 시 예시 모드 폴백 — 심사 기간 중에도 링크는 항상 무언가를 보여준다
- 1건당 비용 실측 $0.20. 비용의 88%가 출력 요금이라는 실측으로 절감 우선순위를 교정

## 7. 로드맵 — 확장성과 해자

혼자 일하는 사람의 수주 사이클 중 지금은 ③만 구현했다.

```
① 노출 → ② 유입 진단 → [③ 견적·범위] → ④ 계약 → ⑤ 수행 → ⑥ 정산·회고
```

④(계약)는 현재 출력(계약 전 질문·범위 문구)이 그대로 이어지는 다음 걸음이다.
⑥(회고)에서 실제 소요 시간이 쌓이면 ③의 공수 추정이 데이터로 보정된다 —
**추정치가 실측치로 바뀌는 순환**이 이 서비스의 해자다.

## 8. 데모 안내

1. https://backstop-seven.vercel.app 접속 → 예시 버튼 3개 중 선택 (또는 요청문 직접 붙여넣기)
2. 대기 중 "1부 — 요청문에서 읽어낸 것"으로 Stage 1 결과를 먼저 확인 (10초)
3. 1~2분 후 계기판(판정 → 금액 대비 → 숨은 작업 목록 → 계약 전 질문) 도착
4. 각 항목의 「요청문 근거 보기」로 인용문 확인 · 「결과 전체 복사」로 제안서에 바로 사용
